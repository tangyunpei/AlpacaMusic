# QQ 音乐直接连接

QQ 音乐 provider 由 Swift 直接请求 QQ 音乐自己的 HTTPS 地址，无需启动 Node 服务、填写兼容 API 地址或使用第三方公共代理。用户只在 AlpacaMusic 的独立官网窗口自行完成登录；provider 接收应用登录流程提供的会话 Cookie，不读取系统浏览器、密码、扫码确认内容或其他账户。

这不是腾讯提供的稳定第三方 SDK。下列协议来自当前官网可公开读取的脚本与上游接口定义，平台可能调整。连接成功必须经过服务器对当前登录账户的确认，不能只根据 Cookie 存在来判断。

## 接口与实现

| 功能 | 官方地址或 RPC | 本应用行为 |
| --- | --- | --- |
| 验证当前账户 | `https://c.y.qq.com/rsc/fcgi-bin/fcg_get_profile_homepage.fcg` | 按官网使用 `userid=0`、`needNewCode=0` 查询本人；要求 `code=0`、有效昵称，以及相符的数字 UIN 或下文限定的加密身份形态 |
| 搜索歌曲 | `https://u.y.qq.com/cgi-bin/musics.fcg` → `music.search.SearchCgiService / DoSearchForQQMusicDesktop` | 使用当前账户、正常网页登录参数和请求签名；最多返回 40 条；平台过滤不会显示成“没有结果” |
| 创建的歌单 | `https://c.y.qq.com/rsc/fcgi-bin/fcg_user_created_diss` | 分页读取，排除 QQ 空间背景音乐等非普通歌单 |
| 收藏的歌单 | `https://c.y.qq.com/fav/fcgi-bin/fcg_get_profile_order_asset.fcg` | 以 `reqtype=3` 分页读取，与创建的歌单去重合并 |
| 歌单曲目 | `musics.fcg` → `music.srfDissInfo.aiDissInfo / uniform_get_Dissinfo` | `disstid` 必须为正整数 JSON 值；使用官网 `song_begin`、`song_num` 分页；重复或缺失分页报错，不将部分结果冒充完整列表 |
| 歌曲资料 | `musics.fcg` → `music.pf_song_detail_svr / get_song_detail_yqq` | 播放前按 MID 确认歌曲及类型；歌单曲目缺有效 MID 时可按数字 `song_id` 单独补资料 |
| 授权播放地址 | `https://u.y.qq.com/cgi-bin/musicu.fcg` → `vkey.GetVkeyServer / CgiGetVkey` | 唯一播放请求路径；使用本会话已有播放票据，按详情真实 `file.media_mid` 请求一个 `M500` 普通 MP3，不探测其他音质或回退接口 |

歌单中一条资料无法解析时继续读取后续曲目和所有分页，不能将部分结果当作完整成功返回。仅在分页完整、总数一致、没有重复页且至少一首可读时，抛出 `MusicError.incompletePlaylist`，附可读取曲目、总数、失败数及最多 20 条原始位置的安全原因；超过 20 条说明未展开数量。界面必须由用户明确选择后才能导入可读取部分。整页请求失败、缺页、总数变化、重复页和取消均不提供部分候选；全不可读仍为普通失败。重复页通过原始列表的稳定摘要判断，整页曲目都坏不会阻止读取下一页。诊断不显示曲名、账号、Cookie 或原始值；用户摘要采用普通中文，详细原因仅保留字段类别、行号和平台错误码。

搜索和歌单共同解析扁平曲目，以及单层 `track_info`、`songInfo`、`songinfo`、`song` 对象；多个包裹字段或非对象包裹值报格式异常，不拼接冲突字段。优先选择合法的 `mid` 或 `songmid`，避免空 `mid` 遮住有效别名。该结构兼容按用户提供的 [simple-music 公开接口实现](https://github.com/Yyyangshenghao/simple-music/blob/master/server/lib/qq-client.ts) 所示字段契约独立编写 Swift，并由注入式测试验证；没有移植其代码。该参考项目会过滤缺 MID 曲目，本实现不采用该行为。

两种 MID 都无效时，仅在 `id`/`songid` 给出不冲突的有效正整数后，使用同一元数据会话调用详情 `song_id`。此参数由[官网当前 common 脚本](https://y.qq.com/ryqq/js/common.chunk.80d50705ce8f47a01eb5.js) 的歌曲详情调用确认。数字字符串必须为十进制整数并在 Int64 正值范围内；布尔、小数、零、负数和溢出值均不能触发补取。详情必须业务成功、`track_info.id` 与所请求编号严格相符、MID 为合法文本且资料可解析，才按原位置加入曲目。每次导入最多 20 次补取，相同数字 ID 复用本次成功或失败结果，不把数字 ID 编造为 MID。补取业务失败、超时、编号冲突或达到上限均记录该条失败并继续读取；取消仍立即传播。只有整份原始分页已读完才可能提供手动部分导入候选。

用户已复现一份 82 首歌单在第 15 首 MID 格式检查失败，该条数字 ID 补资料返回业务码 500；不能由此断定下架或权限原因。新增测试覆盖该形态产生全部 81 首候选和准确的第 15 首失败、后续分页失败不提供候选、整页全坏仍继续读下一页、失败缓存、原因数量上限，以及原有的顺序、精确身份、20 次补取上限、超时和取消。真实部分导入仍需用户选择并实机确认。

元数据请求中的 `QQWebSigning` 使用 CryptoKit 实现 `zzc` 请求摘要。SHA-1 在这里仅用于兼容平台现有的公开请求校验协议，不用于存储密码或提供密码学安全保证。签名覆盖最终发送的 UTF-8 JSON 原始字节，不能先签名再重新序列化。会话票据通过受域名限制的 HTTPS Cookie 发送；专用播放请求还把选定票据放在同一官方主机的 JSON `comm.authst` 中。票据不放入 URL、日志或错误文本。

元数据 RPC 对齐官网浏览器封装的 `uin`、`ct=24`、`cv=4747474`、`notice=0`、两种 CSRF 参数等字段。`comm.uin` 严格采用官网规则：去掉可选 `o` 前缀后，少于 14 位的数字编号编码成 JSON 数字；14 位及以上保留原始数字字符串，避免精度损失。专用播放请求的 `comm.uin` 和 `param.uin` 则均为字符串；其 `comm` 单独使用 `ct=19`、`cv=0`、`format=json`、真实 `authst`，不混入浏览器 CSRF 参数或猜测 `tmeLoginType`。票据仅来自当前应用官网窗口。

官网当前的浏览器运行时还会调用 `__TmeWebSec_sign` 与 `__TmeWebSec_seccgi`，使用 `ag-1` 封装。本实现的元数据使用 `zzc + musics.fcg` JSON 兼容协议，播放使用下文记录的 `CgiGetVkey + authst` 专用契约；没有执行、复制或打包官网混淆脚本，也没有实现 `ag-1`。匿名公开接口已证明该兼容请求形式当前被服务器接受，但这不等于所有登录态接口均已实测。若平台关闭该形式，应更新协议并验证，不能静默改用第三方解析服务。

## 登录态与权限

- QQ 登录读取 `uin`、`qqmusic_uin` 或 `p_uin`；微信登录优先使用 `wxuin`。身份比较使用十进制字符串，去掉可选 `o` 前缀与前导零；例如 Cookie 的 `o0012345678` 与服务器返回的整数 `12345678` 应视为同一账号。微信长编号不经过浮点转换。
- 官网本人资料允许 `creator.uin` 缺失，并把本人的 `creator.encrypt_uin` 用于身份映射；这个本人查询逻辑由 QQ 和微信登录共用，并不限于微信。本应用仅在有效平台会话、请求确为 `userid=0`、服务器返回 `code=0`、`creator` 存在且昵称非空时，接受数字 UIN 缺失、空值或零，同时要求非空且有界的 `encrypt_uin`。应用内账户 ID 仍使用当前会话的规范化 UIN；加密字段不解密、不显示、不写入日志或持久化。
- 如果服务器返回有效数字 UIN，始终要求它与会话一致；即使同时有 `encrypt_uin`，也不能覆盖数字身份冲突。损坏的非空 UIN、缺少加密标识、空昵称和服务器非零状态均会拒绝。加密标识的 512 字节上限及禁止空白、控制字符是应用输入检查，不代表官网公布了固定加密格式。
- 播放票据依次选择现有 `qqmusic_key`、`qm_keyst`、`music_key`、`wxskey`；它们不是应用生成的新票据。只有 `p_lskey` 的会话仍可验证资料，但播放会明确提示缺少播放票据。每次只读取匹配本次官方请求主机及路径、未过期的 Cookie，同名票据按最长匹配路径优先，与 HTTP Cookie 顺序一致；不读取其他浏览器、不交换或伪造票据。CSRF 与登录票据的选择规则不同：新 CSRF 依次读取 `qqmusic_key`、`p_skey`、`skey`、`p_lskey`、`lskey`；旧 CSRF 仅读取 `skey`、`qqmusic_key`。无候选时保留官网初值 `5381`，不把 `qm_keyst` 或其他票据补进散列。过期、域名不匹配或缺失的会话 Cookie 在发送请求前被拒绝。
- Cookie 过滤、HTTPS 主机白名单、禁止跨主机重定向、响应大小限制和取消检查由 `NativeMusicHTTP` 统一执行；会话持久化和退出清理由应用登录管理器负责。
- 会员、付费专辑、版权地区、登录过期等限制由平台决定。空 `purl`、非零返回码、试听文件或不受信任的音频主机直接失败，不尝试其他账户、公共服务、音质升级、解灰或解密。未知返回码只显示失败步骤及码值，不猜测为会员或地域限制；平台未提供链接时提示用户到官网查看该歌曲的可播放状态。
- 每次激活歌曲重新取得播放地址；现有 `Track.url` 即使存在也不会被 QQ provider 作为有效授权地址复用。
- 音频只允许 QQ 音乐 CDN（`*.qqmusic.qq.com`、`*.music.tc.qq.com`），转为 HTTPS；不将账户 Cookie 交给音频 CDN。依次检查平台返回的 `thirdip`、`sip` 候选，前者不合法不会遮蔽后者；仅在两者均没有候选时采用官网同样使用的 `ws6.stream.qqmusic.qq.com`，不会把已返回却被拒绝的地址替换成固定 CDN。绝对 `purl` 保留其原始主机。原始 HTTP 地址的显式默认端口 `80` 在升级 HTTPS 时清除；原始 HTTPS 的 `80` 端口以及任意 `8080` 仍被拒绝。只接受 MP3、M4A、AAC、FLAC、WAV、AIFF、MP4 等播放器支持的普通格式；拒绝 `RS` 试听路径、加密格式及不受支持的格式。播放只接受平台返回的普通媒体 URL，不请求或使用解密密钥；返回文件名若与所请求普通文件不符，直接拒绝。

## 验证边界

2026-10-01 的匿名网络检查未登录任何真人账户，也未请求或下载歌曲音频：

1. 官网搜索页面 HTTP 200；公开脚本表明搜索前调用 `isLogin()`，未登录会打开登录窗口。
2. 当前账户 profile 匿名请求返回 `code=1000`，符合未登录状态。
3. 裸请求与 `zzc` 签名搜索均返回业务过滤标志 `meta.is_filter=-2`。实现将它视为平台限制，而非成功的空搜索。由于没有登录，不能据此确认或否认登录后搜索结果。
4. 使用 `zzc`、`musics.fcg`、与应用一致的 User-Agent 读取公开 `music.musicsearch.HotkeyService / GetHotkeyForQQMusicMobile`，返回 HTTP 200、总返回码 0、RPC 返回码 0 和 30 条公开热词。此为独立网络探针的协议验证，不是登录功能端到端验证。
5. 针对歌单曲目读取进行匿名对照：同一歌单 ID 和其他参数不变，`disstid` 为 JSON 字符串时总返回码 0、RPC 返回码 `10006`；改为 JSON 整数时总返回码、RPC 返回码、资料返回码均为 0。该对照确认本次导入错误的参数类型缺陷，不能把 `10006` 一概解释成登录或会员问题。未请求歌曲音频。
6. 注入式 Swift 测试覆盖会话缺失、失效 Cookie、本人身份匹配、Cookie 与返回值的前导零归一化、微信字符串及 JSON 整数长 UIN、QQ 与微信隐藏数字 UIN 的本人加密身份形态、数字身份冲突不可回退、无效或不完整加密资料拒绝、签名、搜索过滤、歌单合并与分页、歌单 ID 数值类型、官网创建歌单总数字段 `totoal`、重复分页、专用 CgiGetVkey 请求、真实媒体编号、单个普通文件、票据域/路径/过期检查、各响应层拒绝，以及 `thirdip`/`sip` 响应、每次刷新授权地址、拒绝试听/未知主机/加密文件、不泄露原始错误、超时传播和取消后拒绝迟到响应。

此前对网页协议使用明确不存在的测试歌曲标识进行一次无 Cookie 的 `GetUrl` 请求，得到总返回码 0、RPC 返回码 1000（未登录），没有取得或下载音频。此结果只能证明请求到达登录校验，不能证明真实账户播放成功。若平台返回 OGG 或专有加密文件，应用会明确报告不支持，不将其伪装成可播放 MP3。

开发测试未读取任何真人账户会话。用户已实际完成微信登录并成功导入 QQ 歌单，确认隐藏 UIN 和歌单参数类型修复生效。播放实测仍有每首结果码 `104003` 和音频地址格式失败，尚未确认播放成功。候选顺序、端口和专用票据请求已由注入式测试覆盖，真实播放仍需更新后复测。用户报告同账号的官方 App 可播放《With You》；这不能据此推定网页会话请求一定成功，也不能把当前失败归为账号无权。所查官网公开播放器脚本没有给出 `104003` 的精确定义，不能仅凭此码断言会员、版权或地区原因。最低 macOS 26 的可用性以 SDK 27 编译检查为准；本次没有在 macOS 26 实机运行。

为定位 CDN 兼容问题，音频地址被拒绝时最多显示三个主机名，每个不超过 253 个 ASCII 字符且仅允许字母、数字、连字符和点；不输出完整 URL、路径、查询参数、端口或用户认证信息。无法取得可安全显示的主机时，只显示首个失败候选的固定类别：无法解析、缺少协议、协议不受支持、缺少主机、IP 地址格式不受支持或主机名格式不受支持。原始音频路径无法解析也单独提示；不支持的认证信息或端口另行提示。此诊断没有扩大音频主机白名单，任意 IP 和未验证主机仍被拒绝；只有取得官网依据后才应调整信任范围。测试覆盖带签名查询、账号参数、userinfo、端口、IP 及超长主机的脱敏和拒绝行为，以及合法 `sip` 不被无效 `thirdip` 遮蔽、候选优先顺序、HTTP 默认端口归一化、非空错误响应不强加默认 CDN、绝对 URL 不更换主机。

账户校验不会仅凭 Cookie 存在就通过。服务器必须通过本人资料请求返回身份信号；有数字标识时严格比较，隐藏数字标识时采用上述官网加密身份形态。校验失败分别提示缺少账户资料、缺少有效账号标识、身份不一致或缺少昵称；隐藏或无效标识进一步给出“数字标识字段格式不支持”“缺少加密标识”“加密标识字段格式不支持”等固定类别。错误中不包含 Cookie、账号编号、昵称或原始服务器响应。普通网络失败也会返回提示，单次网络请求使用 15 秒请求超时和 25 秒资源超时。官网 WebKit 登录窗口读取本窗口 Cookie 的步骤属于独立流程，不能由 HTTP 超时覆盖。

用户提供的 simple-music 把 `qqCookiePlaybackKey` 用作已有 Cookie 的选择函数，并不是名为该字段的新 Cookie。其 `104003` 分类按票据存在与付费提示分支推断，并非平台公布的错误定义。本应用仅参考请求端点、字段和票据事实，保留未知原因提示；没有复制它的推断分类、多档音质探测、原始服务器消息输出或失败后登录放行。

本轮只调整专用播放请求的票据选择顺序，让 `qqmusic_key` 优先于 `qm_keyst`。依据是官网公共票据 getter 的顺序，以及 jsososo 的 `CgiGetVkey.authst` 使用 `qqmusic_key`；官网网页播放器自身采用另一套 `GetEVkey/GetUrl` 请求，并不直接提供这条专用请求的 `authst` 定义。因此这是有来源支持的协议对齐，不是已证实的 `104003` 根因修复；没有读取真人票据确认两种值是否并存或不同。账号身份、端点、普通 M500 文件名及拒绝后不重试的行为不变。

失败诊断写入系统统一日志的 `QQPlayback` 分类，subsystem 使用当前应用 Bundle ID（项目默认 `dev.byalpaca.music`），普通错误正文不增加技术字段。日志只含固定候选名称 `ticket`、两种主候选是否同时有效的 `both_primary_present`、是否值不同的 `primary_differ`；这些布尔值仅比较同一播放请求作用域内的有效票据。日志不包含票据值、UIN、曲目标识、原始错误、URL 或签名，成功和取消不记录此失败诊断。新增注入式回归覆盖两种票据不同值时的优先选择、相同值、旧票据回退、过期、域名/路径不匹配、同名最长路径、诊断内容及成功/取消；本轮落盘时尚未运行，交由主流程统一构建验证。

## 协议依据

## Cookie 协议值与原始请求头

继续核对[当前官网 vendor](https://y.qq.com/ryqq/js/vendor.chunk.d8b4489cbdb338cb0470.js) 发现网页 Cookie getter 会反复 URI 解码后才读取身份、播放票据及 CSRF 输入；此前原生实现直接使用保存的编码值。现在为这些协议字段单独解码，保留 `+` 原义，支持常见重复百分号编码；原始 Cookie 的保存、作用域及 HTTP 头均不改变。无法识别或过度嵌套的编码明确拒绝，不把未经确认的值送入请求。失败日志另增加 `percent_decoded` 布尔值，仍不输出任何凭据值。

官网 common 的登录判断在某一登录类型下还检查 `music_ignore_pskey` 状态 Cookie。现仅保留官网确实设置的该字段，维持原域、路径和有效期；不创建、推导或补填其值，原生账户连接仍须通过服务器本人验证。既有保存会话可能不含该字段，只有正常重新登录才可能获得。

这些后续修正及网页异步音频启动设置合并后，完整 **191 项 / 15 套件** 与 SDK 27 API 审计通过；是否改善具体账号的 104003 仍以真实复测为准。

最终真实复测：《最后一夜》（小茉莉）在原生播放器进度推进至 17.35 秒，确认可播；《With You》仍为 104003，安全诊断确认本次票据并无候选差异或百分号编码。因而该歌曲的问题尚未解决，也不能归为所有 QQ 歌曲均无法播放。失败提示现可手动关闭，实机验证关闭后消失、再次失败时重新出现，重试目标保留。
