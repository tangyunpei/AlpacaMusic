# Platform word timing / 平台逐字时间

## English

NetEase requests `https://interface3.music.163.com/eapi/song/lyric/v1` with `yv`, `ytv` and `yrv` enabled. The eapi envelope is confined to this lyric route; playback, login and playlist behavior remain unchanged. The endpoint and encryption facts were checked against the primary [lyric_new module](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/master/module/lyric_new.js), [request selection](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/master/util/request.js) and [wire envelope](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/master/util/crypto.js). The Swift envelope is independently implemented. YRC uses millisecond sentence and token starts/durations. Valid data is passed directly as `LyricDocument`, without rounding through LRC. The server may omit YRC for a track; missing or invalid word data falls back to returned LRC or the existing `song/lyric` route.

QQ requests `music.musichallSong.PlayLyricInfo.GetPlayLyricInfo` with `songMid`, `qrc=1`, `trans=1`, and `crypt=1`, using the existing cookie-scoped, signed official RPC. Parameters were checked against [L-1124's endpoint declaration](https://github.com/L-1124/QQMusicApi/blob/main/qqmusic_api/modules/lyric.py); that GPL implementation was used only to verify protocol fields, and no GPL decoder code was ported. QQ's hexadecimal payload is decoded using a Swift adaptation of MIT [qrc-decoder](https://github.com/apoint123/qrc-decoder/tree/cabea11ca2c1437858caaf7d51d9611e6a33bd77), with original MIT [LyricDecoder](https://github.com/SuJiKiNen/LyricDecoder/tree/36fc1eaf31f8ef14a23de6f9f1427ce04178a900) attribution. Full notices are [included](../LICENSES/QRCDecoder-MIT.txt) in both repository and application resources. The custom DES-like transformation is specific to lyric compatibility and uses no deprecated system DES API.

Decompression uses Apple's current [Compression framework](https://developer.apple.com/documentation/compression/compression_zlib), which consumes raw DEFLATE; the decoder verifies the surrounding zlib header and Adler32 checksum and limits decoded text to 2 MB. XML external entities and DOCTYPEs are rejected. QRC's literal attribute newlines are preserved before XML entity decoding. Measured word and sentence timestamps, including gaps and tails, remain authoritative. A malformed optional format triggers the established LRC fallback, never guessed platform timing. Cancellation never starts a fallback request; the surrounding NativeMusicClient retains its existing account-scope validation.

Validation includes original synthetic multilingual fixtures, an encrypted vector generated by the independent MIT TypeScript reference, an eapi vector generated using Node's independent AES implementation, corrupted/truncated/oversized rejection, translations, official request fields, legacy fallback and cancellation. These tests establish parser and transport behavior; they do not promise word data for every track or account and do not claim a logged-in live platform check.

## 简体中文

网易云新增请求 `https://interface3.music.163.com/eapi/song/lyric/v1`，启用 `yv`、`ytv`、`yrv`。eapi 封装只用于这个歌词端点；播放、登录和歌单流程保持不变。端点、加密和默认请求方式交叉核对了第一手来源：[lyric_new](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/master/module/lyric_new.js)、[请求方式](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/master/util/request.js)、[报文格式](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/master/util/crypto.js)。Swift 报文封装独立实现。YRC 提供毫秒级句子及字词的开始时间和时长，有效数据直接进入 `LyricDocument`，不经 LRC 舍入。平台可能不提供某首歌的 YRC；数据缺失或无效时使用返回的普通 LRC，必要时调用原有 `song/lyric` 端点。

QQ 使用既有账号作用域、签名和官方 RPC，请求 `music.musichallSong.PlayLyricInfo.GetPlayLyricInfo`，参数包括 `songMid`、`qrc=1`、`trans=1`、`crypt=1`。协议字段核对了 [L-1124 的端点声明](https://github.com/L-1124/QQMusicApi/blob/main/qqmusic_api/modules/lyric.py)，没有移植其 GPL 解码器代码。十六进制数据通过 Swift 适配的 MIT [qrc-decoder](https://github.com/apoint123/qrc-decoder/tree/cabea11ca2c1437858caaf7d51d9611e6a33bd77) 解码，并保留原始 MIT [LyricDecoder](https://github.com/SuJiKiNen/LyricDecoder/tree/36fc1eaf31f8ef14a23de6f9f1427ce04178a900) 的归属。两个完整声明[随仓库与应用资源分发](../LICENSES/QRCDecoder-MIT.txt)。这个私有 DES 类变换只用于歌词格式兼容，不调用已弃用的系统 DES 接口。

解压使用 Apple 当前的 [Compression](https://developer.apple.com/documentation/compression/compression_zlib) 框架处理原始 DEFLATE，额外校验 zlib 头和 Adler32，并将解压文本限制在 2 MB。拒绝 XML 外部实体及 DOCTYPE；在标准 XML 解码前保留 QRC 属性内的换行。平台提供的字词时间、句子时间、停顿和尾音优先保留。可选格式异常时回退既有普通 LRC，不把猜测当成平台逐字时间；取消不会触发回退请求；外围 NativeMusicClient 保留原有的账号作用域校验。

验证使用原创中英文字词样本、独立 MIT TypeScript 实现生成的加密向量、Node 独立 AES 实现生成的 eapi 向量，并覆盖损坏、截断、超限、翻译、官方请求参数、旧接口回退和取消。这些验证证明解析与请求逻辑，不承诺每首歌或每个账号都有逐字数据，也不等同于真实登录后的平台联调。
