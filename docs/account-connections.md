# 在 AlpacaMusic 内连接网易云与 QQ 音乐

无需部署兼容服务、填写 API 地址、安装 Node 或 Docker。应用使用 Swift 直接访问平台网页接口；默认使用应用内扫码窗口，承载网易云官方扫码组件，以及 QQ 音乐官方 QQ／微信授权组件。

## 使用

1. 打开侧栏“音源”，选择“登录网易云音乐”或“登录 QQ 音乐”。
2. 网易云使用手机网易云音乐 App 扫一扫；QQ 音乐可切换“QQ 扫码”或“微信扫码”，使用对应手机 App。授权范围、平台协议与安全确认仍由用户自行阅读和操作。
3. 手机确认后，窗口自动向平台验证当前账户并连接曲库；只有验证通过且会话保存成功后，音源卡片才显示昵称和已连接。过期或失败时可刷新二维码。
4. 使用顶部搜索框搜索歌曲，或点击“导入我的歌单”选择原有歌单。导入后出现在 AlpacaMusic 的音乐库和左侧歌单。
5. “重新登录 / 切换账号”可重新连接；“退出”清理此平台在本应用保存的登录信息，暂停该平台当前曲目，保留已导入的歌单资料。

若平台要求验证码、安全验证或手机确认，请在平台页面自行完成。应用不会绕过这些要求。关闭登录窗口会取消连接并清除本窗口的临时会话；未完成的新登录不覆盖已连接的旧账号。

## 导入与播放

- 导入保存歌曲标题、艺术家、专辑、封面地址和平台曲目 ID，不下载歌曲音频。
- 重新导入同一账户的同一歌单会补充新曲目，保留本地编辑，不创建重复歌单。不同账户的同名或同 ID 歌单分别保存。
- 本应用修改不会写回原平台；这是一份可更新的本地歌单副本，尚非自动、双向同步。
- 播放时使用当前登录账号重新请求地址；订阅、购买、地区及曲目可用性仍由平台判断。没有权限或仅提供试听时，界面会显示原因。
- 首次搜索每源返回有限条目；当前还没有搜索结果分页 UI。
- 未登录时不会自动连接平台。后续启动会尝试恢复本应用此前保存的会话，失效后可重新登录。

## 会话与实现

网易云与 QQ／微信官方扫码组件均使用独立的 `WKWebsiteDataStore.nonPersistent()` 登录环境。登录窗口不读取 Safari、Chrome 或其他应用的 Cookie。每次刷新或切换扫码方式都会失效旧任务；导航限制在平台和其登录服务的 HTTPS 主机。音源入口默认使用 `QRLoginView`；窗口底部保留“使用网页登录”，可在扫码组件显示或额外验证异常时切换至完整官网的 `DirectLoginView`，无需断开已有账号。网易云 8821 表示本次扫码需要官网安全验证码，新窗口由官方组件显示并承接用户完成的验证，不会仅通过刷新二维码或持续轮询处理。具体依据与当前验证边界见[网易云扫码登录](netease-qr-login.md)。

原生请求仅接收平台会话所需的 Cookie 名称和域，按域、路径与有效期匹配；不使用系统共享 Cookie 存储，不允许请求将 Cookie 重定向到其他主机。凭证只保存于本机钥匙串的 `dev.byalpaca.music.direct-session.v1` 服务，分别使用 `netease` 和 `qq` 条目；不会写入普通曲库 JSON、偏好设置或日志，也不进行 iCloud 同步。代码使用现行 `SecItem` API。

应用每次重建都使用 ad-hoc 签名时，签名身份绑定的是单个二进制版本，钥匙串可能分别重新询问网易云与 QQ 两个条目的访问权限。应固定本机签名配置，见[构建签名](apple-music-setup.md)。第一次由旧的临时签名切换到正式身份时，两个旧条目仍可能分别需要用户授权；系统的“允许”仅针对本次，“始终允许”才会记住该应用身份。应用不代操作系统授权，也不改变条目的访问控制。正常退出不会删除凭据；平台会话失效或钥匙串锁定仍需相应处理。[Apple 代码身份说明](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)

登录、取消、切换账号与退出带有代次检查和独立尝试 ID。取消窗口可以回滚尚未完成展示的连接；已排队的凭证删除在先前写入结束后执行，旧请求不能在退出后重新激活账号或提交曲库结果。

“高级：自定义服务”保留给已有自托管服务的用户，默认折叠。已登录的同平台账号优先，原生登录凭证不会交给自定义地址；直连出错也不会自动转发给它。

这些网易云与 QQ 适配使用网页协议，**不是取得平台合作资质的官方开放 SDK**。平台更改网页登录、请求签名或风控机制时，可能需要更新适配。协议证据与边界见 [网易云直连](netease-direct.md)、[QQ 直连](qq-direct.md)。Apple Music 继续使用原生 MusicKit，Spotify 仍仅提供官方打开入口。

## 验证边界

自动测试使用合成 Cookie、内存凭证存储和注入接口响应，覆盖账户校验、分页、播放权限、取消与切换、请求隔离和歌单持久化。WebKit 隔离测试只注入测试 Cookie，不使用真实账户。2026-10-04 的网易云扫码更新已对照官网当前 `CtWebLogin` 组件；本轮真实手机确认和 8821 安全验证码完成后的连接仍待联调，不能用此前网页登录成功代替。

已另外匿名请求公开端点，确认网易云 weapi 身份/搜索响应，以及 QQ 签名公开热词响应。官网界面检查不会扫码、输入真实凭据、同意协议或完成真人登录。用户后来自行在隔离检查实例连接网易云并导入歌单，观察到曲目播放状态和进度。QQ 真人连接、真实账号持久化恢复、各类订阅或地区权限及平台安全验证完整流程仍需继续联调。

UI 验证可设置 `ALPACA_EPHEMERAL_ACCOUNTS=1`，令该次运行仅使用内存会话，连同 `ALPACA_DATA_DIR` 与 `ALPACA_PREFERENCES_DOMAIN` 隔离检查；普通构建默认使用本机钥匙串。

登录按钮会在可信官网主页面开始显示后启用，不等待广告等子资源全部完成。QQ 登录按钮曾因加载状态未触发 Observation 更新而保持禁用；当前已补上状态通知和回归测试。

主页面、子页面和新窗口的导航被拦截时，窗口现在都会显示协议与主机名；不显示可能包含授权码的路径、查询参数、用户信息或片段。无法显示的网页响应也会给出提示，避免子页面被静默取消后只剩等待画面。

此次匿名核对 QQ 官方授权页及其引用的[公开登录脚本](https://qq-web.cdn-go.cn/monorepo/8d0cd223/ptlogin/js/c_login_2.js)：当前 QQ 音乐授权链涉及 `graph.qq.com` 与 `xui.ptlogin2.qq.com`；[官方登录回调页](https://graph.qq.com/oauth2.0/login_jump)通过父窗口消息继续流程。脚本中“扫描成功，等待手机确认”对应平台状态 `67`，不能仅凭这个画面判定授权已经完成或回调被应用拦截。

随后用户自行在手机 QQ 确认登录，新版窗口明确显示被拦截的子页面主机为 `https://ssl.ptlogin2.graph.qq.com`。依据这次真实界面证据，将这个精确主机加入 QQ 登录窗口名单，修复确认后的回调被阻断；仍拒绝 HTTP、非标准端口、带用户信息或相似域名的地址，网易云窗口不接受该主机。没有添加域名通配符，也未扩大原生接口或凭证提取范围。回调放行的策略测试通过不等于所有 QQ 登录及安全验证场景已完成真人联调。
